# ARCHVIZ Production v0.2 — локальный workflow

## Что готово

Нативный граф ComfyUI: **Facade → Road/Sidewalk → Greenery → People → Final Consistency → Upscale → Post Upscale QC → Inspector/Export**.

Каждый проход включает Processor, Local Composite, проверку сохранности пикселей и сохранение кандидата. Они объединены в одну ноду, чтобы переключатель группы не мог случайно отключить защиту или ручное принятие. Пять групп включаются через **Fast Groups Bypasser (rgthree)**. Режимы RUN/CACHE/SKIP и решения собраны в MASTER.

Это рабочая техническая версия с ручной художественной проверкой. Название Production описывает устройство состояний; оно не означает автоматически подтверждённое коммерческое качество.

## Файлы и установка

- `workflows/ARCHVIZ_Production_v02.json` — открывать в интерфейсе ComfyUI.
- `workflows/ARCHVIZ_Production_v02_API.json` — для программного выполнения; виртуальной панели rgthree в API нет.
- `custom_nodes/archviz_production/` — шесть новых типов нод. Обычные ноды не обеспечивают весь контракт, поэтому JSON требует этот пакет.
- `input/archviz_demo_v02/` — синтетическая техническая картинка и маски для smoke test. Если бинарных demo-файлов нет в checkout, `install_lab.py` автоматически создаёт их через `generate_demo_assets.py`. **Это не образец качества AI.**
- `install_lab.py` — добавляет только эти новые файлы в LAB. Совпадающие файлы пропускает, несовпадающие не перезаписывает.

Целевой LAB: `C:\ComfyUI-Installs\ARCHVIZ_LAB\ComfyUI`.

После добавления custom node pack нужен обычный перезапуск LAB и обновление страницы. Установщик сам процессы не останавливает. STABLE, библиотеки Python и конфигурация моделей не меняются. Веса остаются на D: и читаются через существующий `folder_paths`.

## Первый запуск

1. Открыть `ARCHVIZ_Production_v02.json`.
2. Для проверки интерфейса оставить demo, `action=INSPECT`, нажать Queue. Генераторы не вызываются.
3. Для своего проекта задать новый `project` латиницей, например `courtyard_001`, выбрать исходник в LoadImage и подготовить маски такого же размера. Заменить все пути `archviz_demo_v02/...` в проходах.
4. Установить `action=EXECUTE`, `facade_mode=RUN`. Остальные режимы пока SKIP. Нажать Queue.
5. В Inspector/PreviewAny появятся preview и `attempt_id: a_...`. Следующие проходы остановятся до решения.
6. Проверить материал, окна, силуэт, масштаб текстуры, свет и швы. Для принятия: скопировать `attempt_id` в `target_id`, поставить `reviewed=true`, заполнить `review_note`, выбрать `action=ACCEPT`, Queue. Для отклонения выбрать REJECT.
7. После принятия: `facade_mode=CACHE`, `road_mode=RUN`, `action=EXECUTE`, Queue. Повторить для Greenery и People.
8. Для Upscale: предыдущие принятые проходы CACHE, `upscale_mode=RUN`, `upscale_method=CONSERVATIVE` или GENERATIVE. Результат также требует ACCEPT.
9. Для финальной выдачи: все нужные принятые проходы CACHE, `upscale_mode=CACHE`, `action=EXECUTE`, `export_final=true`. Если Upscale не нужен — OFF/SKIP.

Пустой `*_cache_id` означает поиск **принятой ревизии с точно совпавшим запросом**, а не «последней картинки». В поле можно вставить конкретный `s_...`, но все зависимости всё равно проверяются.

## Режимы и повторные запуски

| Управление | Поведение |
|---|---|
| RUN | Создать Candidate, Composite, QC и `AWAITING_ACCEPT`. Head пока не меняется. |
| CACHE | Прочитать принятую ревизию с совпадающими parent, масками, параметрами и моделью. Генератора нет. |
| SKIP | Передать предыдущий Accepted State без обработки. |
| rgthree OFF | Нода прохода исключается из prompt, AP_STATE соединяется напрямую. Это SKIP, не CACHE. |
| INSPECT | Показать текущий принятый head. Никакой генерации. |
| ACCEPT / REJECT | Выполнить только решение. Генерации в той же очереди не будет. |
| CHECKOUT | Явно выбрать принятую ревизию как head для новой ветки; нужны reviewed и заметка. |

Повторная Queue при прежнем RUN/nonce возвращает сохранённый кандидат без повторной генерации. Для осознанного Regenerate увеличить `run_nonce`. Seed оставлен в режиме **fixed**. Если изменить глобальный seed/checkpoint, старые CACHE зависимых проходов перестанут подходить.

После ACCEPT переключить соответствующий проход на CACHE. Повторный RUN от устаревшего parent блокируется. Для переделки Facade после нескольких принятых этапов: INSPECT → CHECKOUT исходного `original_id` → Facade RUN с новым nonce → заново принять и пересчитать зависимые проходы. Старые ревизии остаются на диске.

При прерывании между запуском модели и записью результата запрос помечается неполным. Автоматического повторного вызова нет: после разбора причины нужен новый nonce.

## Маски

Пути относительны папке `ComfyUI/input`. Формат: одноканальный/серый PNG, белое означает выбранную область. Размер каждого файла должен совпадать с исходником.

- EDIT — зона материала или объекта.
- PROTECT — жёсткий запрет изменения пикселей; имеет приоритет над остальными масками.
- INFLUENCE — явно подготовленная зона контактных теней/взаимодействия.
- COMPOSITE — мягкий вес вклейки, допускается feather.

EDIT/PROTECT/INFLUENCE бинаризуются порогом 0.5. Пустой путь — нулевая маска. Пустой COMPOSITE использует объединение EDIT и INFLUENCE. Пустая эффективная зона запрещает RUN.

```text
alpha = COMPOSITE × max(EDIT, INFLUENCE) × (1 − PROTECT)
result = parent × (1 − alpha) + candidate × alpha
```

При alpha=0 берётся точная копия float32-пикселей parent. Не происходит полного VAE round-trip для финального кадра: модель обрабатывает crop с контекстом, а результат вклеивается только через alpha. Смешивание происходит в числовом RGB-пространстве входа, не в линейном HDR.

Для материалов фасада защищать проёмы, границы здания и значимые швы. Для стекла можно разрешить внутреннюю поверхность остекления, сохранив рамки в PROTECT. Для обработки только камня/дерева использовать соответствующую EDIT-маску и prompt того же Facade Pass.

People использует erase_region=true, чтобы дать модели место для нового персонажа. PROTECT всё равно действует при Composite. Если человек должен перекрывать фасад, такую окклюзию необходимо явно разрешить маской; абсолютный запрет изменения фасада и перекрывающий его человек несовместимы в одних пикселях.

Автоматическая сегментация в этой версии не выполняется. Маски должны быть подготовлены и проверены оператором.

## Backend и стартовые параметры

| Pass | Backend | Denoise | Canny strength |
|---|---|---:|---:|
| Facade | SDXL RealVisXL V4 | 0.24 | 0.65 |
| Road | тот же | 0.28 | 0.55 |
| Greenery | тот же | 0.40 | 0.25 |
| People | тот же, masked erase | 0.85 | 0 |

24 шага, CFG 5, DPM++ 2M / Karras, crop до 1024 px, контекст 96 px. Это стартовые значения, не результат конкурса моделей и не обещание качества.

- Checkpoint по умолчанию: `epicrealismXL_pureFix.safetensors` — используется уже подтверждённая локальная SDXL-модель.
- ControlNet по умолчанию: `xinsirControlnetCanny_v20.safetensors` — используется уже подтверждённый локальный SDXL Canny ControlNet.
- Для первого Conservative Upscale отдельный вес не обязателен: default = `Lanczos (no model)`.
- Canny берётся из неизменяемого ORIGINAL, а не из накопленного результата.
- Conservative upscale: RealESRGAN x4plus или Lanczos; результат приводится к выбранному scale (по умолчанию ×2).
- Generative upscale: SDXL по перекрывающимся тайлам, мягкое объединение, denoise 0.12, detail_blend 0.5. В этом режиме поле upscale_model не используется.
- В Upscale PROTECT сохраняет пиксели **увеличенной Lanczos-базы**. Побитовое сравнение с меньшим исходником после изменения разрешения не имеет смысла.

API, SeedVR2, Qwen/Klein и автоматический выбор backend в этой версии не подключены. Они могут добавляться к тому же контракту после отдельного тестирования. Checkpoint dropdown предназначен для совместимых SDXL-моделей; другие архитектуры не взаимозаменяемы с этим backend.

### Нужно ли скачивать модели

Нет обязательного нового набора моделей специально для ARCHVIZ Production v0.2. Граф приведён к уже подтверждённой локальной библиотеке: `epicrealismXL_pureFix.safetensors` + `xinsirControlnetCanny_v20.safetensors`. Они могут физически лежать на внешнем/общем диске: важно только, чтобы ARCHVIZ_LAB видел их через текущий `extra_model_paths.yaml` / model paths.

Если эти файлы уже есть и видны в dropdown ComfyUI, скачивать их повторно не нужно. Дополнительные модели рассматриваются позже только как кандидаты benchmark, а не как prerequisite установки v0.2.

## QC: что проверяется автоматически

- Число изменённых protected pixels — должно быть 0.
- Число изменений за пределами alpha — должно быть 0.
- Размеры, диапазон значений и конечность чисел.
- Целостность массивов, manifest и QC через SHA-256.
- Принятое происхождение parent и соответствие cache key.
- Advisory-диагностика контуров относительно ORIGINAL: симметричное расстояние Canny edges.

**Контуры не являются geometry truth.** Изменение освещения/материала тоже меняет Canny. Семантические IDs окон, пропущенные/добавленные окна, правдоподобие людей, швы, свет и коммерческая оценка автоматически не подтверждаются: Geometry/Visual остаются NOT_EVALUATED / REVIEW_REQUIRED. ACCEPT требует явной отметки просмотра и заметки. Scene Truth не нужен для работы и пока не интегрирован.

## Состояния и экспорт

Состояния находятся в активной output-папке ComfyUI:

```text
output/archviz_production/<project>/
  state.sqlite3
  s_<uuid>/              # принятые ревизии, включая ORIGINAL
  a_<uuid>/              # кандидаты, в том числе отклонённые
    image.npy            # Composite, точный float32 master
    preview.png          # 8-bit просмотр
    manifest.json
    qc_report.json
    candidate.npy        # сырой результат модели для диагностики
    alpha.npy / masks    # маски попытки
  final_s_<uuid>.json    # указатель финальной выдачи + отчёт
```

Новая ревизия не перезаписывает исходник. Принятие транзакционно меняет head. После перезапуска INSPECT восстанавливает состояние. Полный bundle переносится вместе со всей папкой проекта и SQLite. Во время переноса проект не должен выполняться.

Неизменяемость и хэши защищают от случайной подмены, а не от администратора, который меняет всю базу. Веса моделей идентифицируются путём/размером/mtime; полный многогигабайтный SHA-256 весов не считается на каждую Queue. Для финального растрового просмотра используйте preview.png; точный float32-оригинал остаётся в image.npy.

## Ограничения v0.2

Один RGB-кадр на проект, без batch/video/HDR. Состояние хранится локально, параллельные генерации одной ветки не поддерживаются. Большие изображения требуют заметного места для float32 intermediates. Автоматическое удаление кандидатов отключено. По умолчанию каждый новый проект безопасно открывается в INSPECT / SKIP.
